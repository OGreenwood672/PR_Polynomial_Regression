\begin{abstract}
Efficient modeling of lift kinematics is vital for improving elevator systems to enhancing passenger comfort and run accurate simulations. Current methods involve equations that produce an estimate for the ideal kinematics.
This study aims to evaluate the effectiveness of polynomial regression models in predicting lift kinematics and compare different methods for training the model.
Accelerometer data was collected from 104 lift journeys, encompassing approximately 156,000 data points. Using multivariate polynomial linear regression with varying degrees, we developed models to predict key kinematic parameters: acceleration, velocity, jerk, and displacement. Model performance was assessed using cross-validation and root mean square error (RMSE).
Using our initial method, the models was able to predict value with high $R^2$ scores for velocity, acceleration, and displacement, all exceeding 90\%. The method also yielded good RMSE values, approximately 0.08 for both velocity and acceleration, and 1.8 for displacement. The model produced predicted asymmetric ideal kinematics with two different jerk values.
The second method was specifically designed to optimise the model for predicting acceleration. With this refined approach, the predictions obtained had a significantly improved $R^2$ score of 99\% and an RMSE of 0.03, demonstrating enhanced model accuracy for acceleration predictions. This method also allowed for four different jerk values.
Polynomial linear regression proves to be a robust tool for modeling complex lift kinematics. These findings have implications for more accurate lift simulations and improved passenger experience.
 
\end{abstract}

\section{INTRODUCTION}

Lift kinematics plays a crucial role in the elevator industry, focusing on the movement of a lift car within a shaft without considering mass or force. By measuring accelerometer data from a lift, we can assess the smoothness of its motion and improve passenger comfort based on this analysis. Additionally, this data can help detect potential issues in the lift system before they affect the user experience. This paper presents a method for generating equations for use in both lift simulations and real-world lift systems.

\section{METHODOLOGY}

\subsection{Data Collection}
The machine learning models requires a large dataset for training and evaluating the model. For this model, 104 motion files (.mtn) were collected, each containing raw accelerometer data and timestamps from single journeys in a csv format. These files also contain 3 values at the top representing stages of the door cycle on a lift, these can be ignored.
Each file contained approximately 25 seconds of data, and with 60 data points per second, about 156,000 unfiltered data points were available for training the model.

\subsection{Processing}
As the data from the motion files is raw accelerometer data in its x, y and z components, it must be processed into a single smoothed set of data, which can then be used with the timestamps to calculate the corresponding velocity, jerk and displacement values.

\subsubsection{Acceleration}
Pythagoras’ theorem is applied to the x, y, and z components of the acceleration to calculate the magnitude, and it is multiplied by the sign of the z-component to allow for different orientations of the accelerometer. \\

\begin{align}
M_{\text{acc}} &= \sqrt{(\text{accelerometer}_x)^2 + (\text{accelerometer}_y)^2
+ (\text{accelerometer}_z)^2} \notag \\ &\quad \times \text{sign}(\text{accelerometer}_z)
\end{align}
\\
Smoothing is now applied to $M_{acc}$. This will remove a considerable amount of the noise from the data. The following function is used:

\vspace{2em}
\begin{equation}
    M_{\text{acc}_{i}} = \frac{M_{\text{acc}_i} + M_{\text{acc}_{i - 1}} \cdot \alpha}{1 + \alpha}
\end{equation}
\vspace{1em}

The differentiating that is applied later will greatly exaggerate the noise from the data. This means a very small alpha value must be applied to reduce the noise considerably. A value of $0.025$ is used as it is sufficiently small but not so small that is renders the data unusable. \\

\subsubsection{Assigning Stages}
Stages are needed to be defined at each timestamp so that the behaviour the lift is exhibiting in any given instance of time is known. This will be useful in measurement corrections and splitting the data into phases and periods.

\begin{table}[H]
\centering

\begin{tabular}{|p{0.2\linewidth}|p{0.45\linewidth}|} 
\hline
 \textbf{Stage} & \textbf{Description} \\ \hline
 \textbf{0} & Lift is stationary \\ \hline
 \textbf{1} & Lift is accelerating \\ \hline
 \textbf{2} & Lift is at constant velocity \\ \hline
 \textbf{3} & Lift is decelerating \\ \hline
\end{tabular}

These stages are assigned using a similar algorithm to this dissertation \cite{andrew}:

% \lstinputlisting[language=Python,caption=Assigning Stages]{add_stages.py}
First, an upper and lower threshold for acceleration is defined. A lower bound of $0.1$ was used as it was as low as possible whilst still catching all the 0 acceleration values and accounting for the noise.
A upper bound of $0.5$ was used as it was as high as possible whilst sill catching all the peak
acceleration values.

\vspace{2em}

\begin{equation}
    a^{UB} = a * UB
\end{equation}
\begin{equation}
    a^{LB} = a * LB
\end{equation}

\vspace{2em}

$M_{acc}$ was looped through and simultaneously $C$ was calculated (the number of consecutive instances we find above $a^{UB}$). If C ever satisfies:

\vspace{0.5em}

\begin{equation}
    C >= C_{lim}
\end{equation}

\vspace{0.5em}

Then the algorithm immediately backtracks and determines where $a^{LB}$ was crossed and set all points past that to stage one.
A similar process to this is executed for converting stage one to stage two, stage two to stage three and stage three to stage zero.

\subsubsection{Velocities}
The $M_{acc}$ is integrated with respect to time to compute the $M_{vec}$. Corrections are applied on $M_{vel}$ using the stage values calculated previously. When at stage 0, the velocity is drawn to the value it should be in increments, similar to this dissertation \cite{andrew}.

\vspace{2em}

\vspace{2em}

The effect variable was found through trial and error. For this model, $0.0005$ was used. Higher values would result in velocity having sudden changes when changing to stage zero. Lower values would result in velocity not changing sufficiently.

\subsubsection{displacement and Jerk}
The velocity is integrated to compute the $M_{displacement}$ (displacement), and the acceleration is differentiated to compute the $M_{jerk}$ (jerk). No corrections are required for these values.

For each phase, $j$, $a$, $v$, and $d$ is calculated and saved. The phases are then translated and transformed so they all start at time 0 at value 0.

\subsubsection{Using the Model}
To use the model, the phases (with the same size buffer zone) must be extracted, and the $j$, $a$, $v$, and $d$ for that phase must be calculated. These values along with all the timestamps are inputted to the model and the predicted velocity is returned.

\paragraph{Calculating Ideal Acceleration}
The velocities are differentiated to get the ideal accelerations. The ideal accelerations are then scaled to match the $M_{\text{acc}}$ and then we cut off any accelerations that are in the wrong direction.

\paragraph{Calculating Ideal Velocity}
For a more accurate ideal velocity, the ideal accelerations are integrated then scaled to $v$ to match the $M_{\text{vel}}$

\paragraph{Calculating Ideal displacements}
To calculate the displacement, the ideal velocity is integrated and a small linear correction is added.

\paragraph{Calculating Ideal Jerk}
The ideal accelerations are differentiated to calculate the ideal jerk values. These values are then smoothed to reduce the noise.

\subsection{Method 2: Using Periods}
In this method, the focus is on optimising the model's acceleration profile predictions. The model is allowed to use different acceleration and deceleration values, this will allow the model to be used in scenarios such as in a two car shaft.

\subsubsection{Splitting the Data}
To split the data into periods, the data is split into phases like in method one but then further split them by finding when $0.9 * a$ is reached and then stopping just before the acceleration goes down again. (To find the other period, simply reverse the data and perform the same method). Small buffer zones are added to each of the periods to help the model learn to start and end on the correct values. Each period then has its $a$, $j$, $v$ and $d$ calculated.

\subsubsection{Using the model}
To use the model, the periods (with the same size buffer zone) must be extracted, and
the j, a, v, and d for that period must be calculated. These values along with all the
timestamps are inputted to the model and the predicted acceleration is returned.

\paragraph{Calculating Ideal Acceleration}
First, each period is transformed so that is it in the correct orientation, then it is translated so that it starts at the correct y coordinate. Any values that are on the wrong side of $y=0$ are removed. Any missing timestamps are removed and then the periods are connected together. Finally the acceleration is smoothed so that there are no jagged jerk values later on.

\paragraph{Calculating Ideal Velocity}
To calculate velocity, the predicted acceleration values are integrated and scaled so the maximum predicted velocity matches $v$.

\paragraph{Calculating Ideal displacements}
The ideal velocity are integrated and a small linear correction is added.

\paragraph{Calculating Ideal Jerk}
The ideal accelerations are smoothed using an exponential weighted average, and then smoothed using equation (2). This prevents the ideal jerk values having too much noise. Finally, the ideal accelerations are differentiated to calculate the ideal jerk.

\section{DISCUSSION}
Although both methods are accurate at at predicting the kinematic profiles, method two is much more accurate, offering half the RMSE. Method two also allows for a more advanced asymmetric kinematic profiles where four different jerk values can be provided unlike method two in which only two jerk values can be provided.

\subsection{Further Improvements:}
Currently, the only data being used is from the accelerometer. This means the model is only predicting what the accelerometer in sensing which for large displacements may be wrong. Adding another sensor and using a Kalman filter would provide results which are more accurate to the real world.

This paper only attempts to model single journeys, however to allow the model to predict multiple journeys would not be too difficult, only changing corrections towards displacement and some other minor edits.

Finally, to model dynamic kinematics, an edit to how the stages work would be required.

\section{CONCLUSION}
This paper shows that polynomial regression can effectively model lift kinematics, offering a valuable tool for improving simulation accuracy and passenger comfort. Whilst the results are promising, the study’s limitations highlight the need for further research with larger datasets. Overall, the findings contribute to the ongoing development of modeling techniques in the elevator industry .
